# O2 server: data-out, retention and backup interfaces

O2b owns desktop passive pull/status UI, pull/restore runbooks and M8 acceptance. No new client dependencies.

## Export wire contract

- `GET /v1/export/member[?member_id=UUID]`: JSON `{format_version:1, exported_at, member_id, tables, appointments_ics}`. App callers export only themselves. Admin PATs may select a live member, including a dependent, but use a synthetic **member** caller and the shared S4b authoritative ACL, never the agent bypass. Other PAT scopes are forbidden.
- `tables` includes visible items/occurrences and assignees/viewers/reminders; visible lists and current children (only list_entries with archived_at IS NULL, and checks of those entries); live readable comments/attachment metadata; recipient-authorized notification projection/preferences; own settings/availability/agenda/reminders/daily load/suggestions; public member/relationship and household projections. ICS source metadata uses the same safe admin-only snapshot projection. It excludes all revision/audit/derivation history, including item_revisions, task_events, list_revisions, list_entry_revisions and item_derivation: current visibility never authorizes pre-share history. It also excludes credential and consumer-control tables. Each projection is reauthorized inside one read-only REPEATABLE READ transaction; no time-window cutoff is imposed on retained occurrences.
- `appointments_ics` is one calendar file produced by `core::ics::write` from readable materialized appointment occurrences, stable occurrence UUID UIDs, effective detached overrides, fixed TZID-local starts (UTC for UTC zones or the later fold), floating local starts without TZID, or all-day dates chosen by item time_mode, skipped occurrences cancelled. K7 later-fold UTC limitation: a fixed start in the second pass of a fall-back hour is emitted in UTC to retain its instant. Third-party clients may expand a recurring UTC master in UTC and shift its local clock across DST. This export emits materialized appointments as standalone VEVENTs (no RRULE), not recurring masters. Save this string as `appointments.ics`.
- `GET /v1/admin/export/household`: streamed gzip tar with v2 `data.json` (`format_version:2`, `exported_at`, `tables` mapping table names to `tables/NAME.jsonl` paths), one JSON Lines entry per allowlisted table, `blobs/aa/bb/SHA256`, and a final `complete.json` entry. App callers must be super admins with single-use `Porchlight-Step-Up` bound to session/device/action `household.export` (obtain with `/v1/auth/reauth`); agents require admin scope. No agent download route for encrypted backups is implied.
- Household data uses an explicit relation allowlist, not catalog discovery. Household-owned relations filter by household_id; child notification tables filter through their event parent, member-only load/retry tables through household_members. Global notification kind/scheduler/backup operational rows belong to this single-household server. Excluded: user_credentials, sessions, enrollment_tokens, password_resets, api_tokens, step_ups, idempotency response caches, calendar feed bearer tokens, installation/control/lease/lock state, member_load_signals (transient planning input), PKI, `.env` and every private filesystem secret. Ordinary data/audit may retain opaque historical actor/PAT identifiers; these are not usable bearer credentials. Feed URLs are user calendar data, not Porchlight feed bearer tokens.
- Household export responds with headers after authorization, before lease/snapshot/table/blob work. An owned producer commits a guarded lease before its read-only RR snapshot. Only the current JSON row is decoded in memory; each table streams through a BufWriter into an anonymous 0600 file under runtime data_dir, is appended to tar, then discarded. The distinct blob hash list is fetched completely inside the RR snapshot; the snapshot is committed before blob output, so no cursor/statement or snapshot connection spans the client-paced blob phase. Metadata memory is proportional to the number of hashes (not blob bytes). There is no whole-data.json buffer or all-blob descriptor inventory. Gzip uses bounded backpressure (64KiB chunks, two queued chunks) and a five-minute deadline per blocked channel write, bounding snapshot/client stalls during table output too. DB waits after lease acquisition cancel on disconnect; guard release runs on completion/disconnect/failure/unwind, with a fixed diagnostic on release error. Crash expiry remains six hours. Unpinned live attachment/thumbnail hashes or unavailable blob files fail the stream closed (headers already sent; clients must reject/remove incomplete downloads). Observed-progress renewals occur during table spooling and compressed/blob output at five-minute intervals; a final live-pin check precedes stream completion. Stalled clients receive no heartbeat renewal.
- Completeness rule for O2b/restore: **an archive without the completion entry is incomplete**. Require `complete.json` to be the LAST tar entry with `{format_version:2, complete:true, table_rows:{NAME:COUNT}, blob_count:COUNT, blob_sha256:[HASH,...]}`; only successful table/blob output, snapshot commit and final live-lease check authorize it. Inventory hashes identify the emitted main/thumbnail files; they are not a new filesystem rehash guarantee. Validate gzip CRC/trailer as well as the marker; restore consumers should compare inventory to extracted entries before applying data. On producer error or unwind, the channel writer is poisoned before tar/gzip drop finalizers, so failures cannot finish a valid gzip stream. A marker without a valid gzip trailer is also incomplete.
- `porch export --member WHO | --household [--out FILE]`: raw stdout if no output file; otherwise create private 0600, refuse overwrite, remove partial file on failure. Household mode verifies the final completion flag and gzip trailer with a bounded streaming decoder before exit0 (even on a successful HTTP response); stdout may already contain partial bytes on failure, so consumers must also honor its nonzero exit and validate the archive. Headers use the normal 15-second request deadline; each streaming body read has a separate 5-minute idle timeout, not a whole-download deadline. Global `--json` with --out returns a byte-count summary, never parses binary tar as JSON. `porch backups` reads agent status.

## Maintenance / derivation inventory

| Relation or column | Authority / regeneration | Domain derivation, revision, outbox | Export / backup |
| --- | --- | --- | --- |
| `stream_retention` · id, epoch, pruned_through (0056) | singleton generated by real committed prefix prune only; epoch monotonic, quiet maximum retained | no item derivation/revision/version; porchlight_stream wake only, held streams terminal resnapshot | internal control excluded from data-only exports; pg_dump includes it |
| `purge_log` · counts (0055/0056) | append-only maintenance audit, injected clock for selection; nightly rows have empty item_ids | no item derivation; immutable existing audit contract | household export + pg_dump |
| `blob_leases` · expires_at (`pl_renew_blob_lease`) | progress-based renewal of a still-live pin; never revive expired | no item derivation/history/outbox | transient control excluded from exports; pg_dump includes current lease state |
| `backup_runs` · status/times/file/size/sha256 | backup producer records independent encrypted publication or controlled failure; no raw diagnostics returned | no item derivation/version/outbox | household data export + pg_dump |
| `notification_kinds` · backup_stale (0057) | R53 INSERT ON CONFLICT only; system hourly producer through existing emitter | deduped event, normal notifier + recipient outbox; fixed safe operational presentation | household export + pg_dump |

`pl_retention(p_now)` is maintenance-owned, fixed-search-path SECURITY DEFINER with explicit grants. Scheduled at **03:45 household local time**, it deletes notifications/events strictly older than 90 days, explicit source/delivery children and expired sessions/enrollment tokens/password resets/PATs/step-ups (`expires_at <= p_now`), counting step-ups that cascade from an expired session as well. Expired-PAT deletion sets comments.author_token_id and attachments.uploader_token_id to NULL via their FK actions, bumping those rows’ versions without business outbox events (S7b token-purge erasure); their content remains. Every per-household table count enters purge_log in the same transaction. Purge never enqueues item derivation. Existing idempotency responses retain their separate **24h** TTL/startup+hourly purge (not a new nightly duplicate).

Published outbox pruning deletes a seven-day **prefix only**, below first recent published sequence; if all are old, retain the global maximum. Unpublished rows never prune. `stream_assign_mutex` serializes publication/pruning; the atomic generation guards held scans, queued delivery and unpolled streams (see stream.md). A generation change sends terminal `resnapshot` reason `retention_pruned` before any further tickles. Open-window bounds still scan outbox; the constant-size epoch is not an indexed-window performance claim.

0055 extends S5 once with explicit counts/deletes of comments, attachments, notification_sources and notification_event_delivery; inbox references are counted/severed, not inbox history deleted. `blob_references` counts distinct referenced blob metadata rows whose 30-day unreferenced clock is reset, including thumbnails. Blobs/bytes and collaboration_audit survive. Every unrecognized FK shape into **any** deletion relation remains a named 409 refusal before audit/domain mutation. No silent second-order cascade; no grants/DDL run in request-path functions.

## Backup producer and O2b download contract

1. Take `pl_take_blob_lease` in an independent committed transaction **before** exporting the DB snapshot/pg_dump. Use S7b final attachments.blob_sha256 + thumbnail_sha256; stream exactly the snapshot's referenced leased hashes. Newly referenced unpinned snapshot hashes fail closed and retry on the next run.
2. Renew every five minutes of observed byte/dump progress with `pl_renew_blob_lease(uuid, interval default '6 hours')`, taking SHARE locks on pinned blob rows in household/hash order. Expired renewal returns false, never extends it. Do not pulse progress for a stuck pipe/query/dump.
3. Force a live-lease check after encryption and again after encrypted SHA-256 hashing, before atomic publication and success DB update; release only afterward or on failure. Crash leases expire. Existing disk-dump/tmpfs-secret staging limits, safe regular-file checks, previous-bundle preservation and release retention remain unchanged.

Status routes (all GET): `/v1/admin/backups` admin PAT; `/v1/backups` and `/v1/backups/latest` super-admin app over mTLS. Status JSON: `{last_success?, next_due?, last_error?, latest?}`; latest: `{id,bundle_file,size,sha256,started_at,finished_at,next_due_at}`. No prior success → latest 404; status latest null. Error text is a fixed private-diagnostics hint, never raw external error text; a later failure makes next_due the one-hour retry instant. Before the first completed run next_due is null (not a fabricated schedule).

`/v1/backups/latest/download` is **mTLS super-admin app only**, streams already age-encrypted octets; no recovery private key lives on server. Bundle path is a constrained basename under configured operator-owned backup_dir, rejects symlinks, uses regular O_NOFOLLOW descriptor and verifies size/full SHA-256 before serving. Mismatch → 409. Response: Content-Length, Accept-Ranges: bytes, ETag = quoted lowercase SHA-256, attachment filename; 206 adds Content-Range. One closed/open/suffix byte range supported; invalid/multiple/unsatisfiable → mapped 416 with `Content-Range: bytes */SIZE`. Matching If-Range resumes; mismatch returns full 200. O2b must validate final local sha256 and restart if latest identity changes; server ETag is metadata, not a client integrity substitute. API Compose mounts backups read-only.

Hourly `backup_stale` producer compares last success (household creation if none) to injected now **strictly over 26 hours**. Only live super-admin profiles; system actor; dedupe key includes recipient + last-success UUID (`initial` before any success). Repeated failures in one episode do not duplicate; new success re-arms. Kind added only by 0057 registry INSERT, safe title/body and operational summary topic on unchanged activity delivery channel.
